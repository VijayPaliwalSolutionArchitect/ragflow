docs(ragflow): replace upstream SECURITY.md with a fork-aware security policy

The shipped SECURITY.md was the raw upstream template: it pointed every
reporter at infiniflow/ragflow, named no SHIVAM ITCS contact, had no
response-time commitment, and embedded a live exploit PoC as the "Steps to
reproduce" section — a document that both teaches an attacker how to
reproduce a vulnerability and routes the report to a maintainer with no
standing to act on it.

A fork that handles client deployments needs a security path its own
maintainers can actually respond to. Replaced it with a policy that:

  - names MD@ShivamITConsultancy.com as the only vulnerability channel and
    states explicitly that public GitHub Issues are not the channel;
  - sets per-severity response and fix targets (24h critical, 48h high, 5d
    medium, next-baseline low);
  - states the supported baseline (the pinned commit only) and that fixes
    land as deliberate fork updates, not ad-hoc cherry-picks;
  - documents the fork's actual posture — no upstream code modified, no
    dedicated security team, local-first data residency — so a reporter is
    not left expecting a security program that does not exist here;
  - routes upstream-source vulnerabilities back to infiniflow/ragflow's own
    policy, which is the only channel that can act on code this fork has not
    touched;
  - removes the embedded exploit PoC, which served no purpose in a security
    policy and only documented an attack path.

No upstream source modified; documentation only.
